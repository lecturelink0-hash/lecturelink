# 출처 추적 — 무엇을 자동으로 검사하고 무엇을 전문가에게 남기는가 (A8)

분담표가 A8을 **"2단계 전체의 선행 조건"**으로 둔 이유부터.

가이드가 대외 발표 최소 묶음에 넣은 **근거 충실도**와 **자료 외 주장률**은, 지금까지
"측정이 어려운" 게 아니라 **비교할 출처가 저장되지 않아 잴 값 자체가 없었습니다.**
문항이 강의자료 몇 페이지에서 나왔는지를 아무 데도 적지 않았기 때문입니다.

그리고 이것 없이 전문가 검수를 시작하면, 검수자가 "근거가 충분한가"를 판정할 때마다
강의자료 전체를 뒤져야 해서 검수 시간이 몇 배로 늘어납니다.

---

## 1. 가장 중요한 경계

가이드 §4.3이 갈라 놓은 두 가지를 코드에서도 갈라 뒀습니다.

| | 무엇 | 누가 판정 |
|---|---|---|
| **구조적으로 존재하는 출처** | 문항이 가리킨 페이지가 그 자료에 실제로 있는가 | **코드** (자동 검사) |
| **의미상 뒷받침하는 출처** | 그 페이지의 내용이 정말 이 문항의 근거인가 | **전문가** (검증) |

**섞으면 안 됩니다.** "출처 유효성 98%"라는 수치가 나오면 그건 *페이지 번호가 존재한다*는
뜻일 뿐 *근거가 맞다*는 뜻이 아닙니다. 대외 발표에서 후자로 읽히면 위험합니다.

코드는 전자만 합니다. `lib/ai/source-refs.ts` 첫머리에 같은 경고를 적어 뒀습니다.

---

## 2. 무엇이 저장되는가

### `material_chunks` — 자료 원문

강의자료를 슬라이드/문단 단위로 잘라 저장합니다. 검수자가 문항의 출처 페이지를 눌러
원문을 바로 볼 수 있게 하기 위한 것입니다.

| 컬럼 | 뜻 |
|---|---|
| `chunk_index` | 자료 안 순번(0-based). **결정론적** |
| `page_index` | 슬라이드/페이지 번호(1-based) |
| `kind` | `slide_text`(저자가 쓴 본문) / `ocr`(그림 속 글자를 기계가 읽음) |
| `content_sha` | 청크 내용 지문 — 자료가 조용히 바뀌었는지 판정 |

**본문과 OCR을 나누는 이유:** 같은 페이지에서 나왔어도 출처의 성격이 다릅니다. OCR은
오독이 섞이므로, 한 덩어리로 묶으면 검수자가 "근거가 충분한가"를 판정할 때 둘을
구분할 수 없습니다.

**청킹이 결정론이어야 하는 이유:** 같은 자료를 다시 처리했을 때 청크 번호가 달라지면
이전에 저장된 문항의 출처가 통째로 끊깁니다.

### `private_questions.source_refs` — 문항별 출처

가이드 §12.2가 예상문제 벤치마크 레코드의 필수 필드로 지정한 `source_refs`입니다.

```json
{
  "fileSha256": "…",
  "pages": [3, 4],
  "chunkIds": ["…", "…"],
  "invalidPages": [99]
}
```

`invalidPages`는 모델이 신고했지만 자료에 없던 페이지입니다. **지우지 않고 남깁니다** —
무엇이 왜 걸러졌는지 추적할 수 있어야 합니다.

---

## 3. 어떻게 얻는가

프롬프트에는 원래부터 `## 슬라이드 3` 헤더가 들어가 있었습니다. **모델은 출처를 보고
있었지만 보고하지 않았고, 저장할 곳도 없었습니다.** A8이 한 일은 그 둘을 붙인 것입니다.

1. 생성 툴 스키마에 `source_pages`를 **required**로 추가 (빈 배열 허용).
   선택 필드로 두면 모델이 조용히 빼먹어 신고율이 0에 가까워집니다 — `image_indices`와 같은 이유입니다.
2. 생성 후 `validateSourceRefs()`로 구조적 검사.
3. 통과한 페이지만 `pages`에, 그 페이지의 청크 id를 `chunkIds`에 담아 저장.

### 기준집합은 "자료 전체"가 아니라 "그 배치가 본 페이지"

배치별 구간 분할(`segmentForBatch`) 때문에, 배치마다 자료의 일부만 봅니다.
자료 전체 페이지로 검사하면 **그 배치가 보지도 못한 페이지를 인용해도 통과**합니다.

그래서 기준집합은 프롬프트에 실제로 실린 `## 슬라이드 N` 헤더에서 뽑습니다
(`pagesInContext`). 회귀 검사에 이 경우가 들어 있습니다.

---

## 4. 나오는 지표

| 지표 | 뜻 |
|---|---|
| `sourceReportRate` | 출처를 하나라도 신고한 문항 비율 |
| `locationValidRate` | **구조적 출처 유효성** — 존재하는 페이지를 가리킨 참조 비율 (가이드 §2.1) |
| `questionsWithInvalidRef` | 없는 페이지를 신고한 문항 수 |

생성 진단(`ai_cost_log.metadata`)의 배치별 항목과 경고에 남습니다.

**아직 안 되는 것:** 근거 충실도·자료 외 주장률은 여전히 **전문가 판정**이 필요합니다.
A8이 만든 것은 그 판정을 *할 수 있게 하는 조건*(원문을 바로 찾을 수 있는 상태)이지
판정 자체가 아닙니다.

---

## 5. 배포

`supabase/migrations/00043_material_chunks_and_source_refs.sql` 적용이 필요합니다.

**미적용이어도 생성은 정상 동작합니다.** 두 겹의 폴백이 있습니다:
- 청크 테이블이 없으면 → 청크 저장을 건너뛰고 경고만 남김
- `source_refs` 컬럼이 없으면 → 출처를 떼고 다시 저장

출처는 있으면 좋은 것이지 문항의 전제가 아니기 때문입니다. 다만 미적용 상태에서는
2단계 근거 검수를 시작할 수 없습니다.
