# 5.2 C·D 출제 계획·질의 생성 결과 (RAG 실행계획 v1.1 · PR G)

2026-10-02 · 전재현 · 도구: `scripts/rag-eval/plan-eval.ts` · 적용: `lib/rag/plan.ts`, `lib/ai/rag-plan.ts`

## 결론

- **계획 콜 1회로 출제 단위 15개(요청 10문항의 1.5배)와 단위별 검색 질의를 만듦.** 질의는 핵심 개념·임상 맥락·감별 비교 3개와 HyDE 가상 발문 1개임. 모델은 gemini-2.5-flash임.
- **사전 기준 5개 중 4개를 충족함.** 근거 충분(P3)만 0.861로 기준 0.90에 못 미쳤음. 허용된 1회 수정 뒤에도 같았음.
- **현행 초점보다 모든 지표에서 크게 나음.**
  - 사람이 검토한 출제 단위(R1)와의 일치: 0.523 vs 0.148. 10건 모두 계획이 우세함.
  - 근거 충분: 0.86 vs 0.38
  - 1위 청크가 다른 단위와 겹치지 않는 비율: 0.87 vs 0.23
- **원가·지연.** 업로드당 약 $0.008이고 문항당으로는 $0.0008로 기준선 $0.0241의 3%임. 지연 p95는 16.6초, 입력은 최대 6.8k 토큰(상한 8k)임.
- **P3 미달은 '근거 없는 주제'가 아니라 τ 보정 문제로 보임.**
  - τ(0.61) 아래로 떨어진 단위 42개 모두 계획이 짚은 쪽을 근거 팩 안에 찾아왔고, 39개는 1위로 찾았음.
  - τ는 R1 질의(정답 청크를 보고 쓴 질의)로 정한 값이라, 요약만 보고 쓴 계획 질의에는 엄격한 것으로 보임.
  - 실행 20회 중 19회는 τ를 넘는 단위가 요청 수(10) 이상이라 예비 단위로 메울 수 있음. 1회는 본문이 거의 없는 스캔 자료(SC1)였음.
  - τ를 계획 질의 기준으로 다시 볼지는 PR H(검색·근거 팩)에서 정함.
- **약어 사전(5.2 D)은 넣지 않음.** R1 정답 질의 596개 중 110개가 확장됐지만 Recall@6이 0.970에서 0.970으로 그대로였음(사전 기준 +0.01 미달).
- **운영 영향.** shadow·on에서만 계획 콜을 돌려 진단(`rag.plan`, 통계만)에 남김. 생성은 아직 단위를 쓰지 않음(PR I부터). off는 바뀌지 않음.

## 1. 설계

**입력(5.2 C).** 페이지 요약과 그림 캡션 목록을 12,000자 안에서 조립함(`buildPlanInput`).
- 요약은 `p쪽번호 제목 — 첫 문장들` 형식임.
- 캡션은 입력의 25% 안에서 먼저 싣고, 남은 글자를 내용 있는 페이지에 고르게 나눔.
- 페이지가 너무 많으면 앞에서 자르지 않고 고르게 솎음. 앞에서 자르면 뒤쪽 내용이 계획에서 빠짐(L5와 같은 실패).
- 계획서는 "헤딩 경로 + 페이지별 첫 2문장"이라고 했음. 텍스트 PDF에는 헤딩 구조가 없어 첫 줄을 제목으로 봄. 첫 2문장은 1차 결과를 보고 '상한 안의 첫 문장들'로 늘림(4장).

**출력.** 도구 호출 스키마는 단위마다 다음 필드를 받음.
- `topic`, `objective`
- `ask_kinds`: knowledge-rules 카탈로그 값
- `needs_image`, `figures`
- `pages`
- 검색어 3개, `hyde_stem`

출력 검사(`parsePlan`)는 다음과 같음.
- 주제가 없거나 같은 주제가 반복된 단위는 버림.
- 카탈로그 밖 유형, 입력에 없던 쪽·그림은 지움. 가리킬 그림이 없으면 이미지 단위가 아니고 이미지형 유형도 지움.
- 빈 검색어는 주제로 채움. 검색은 늘 질의 4개로 함(E1~E3과 같은 방식).

**쿼터 칸 배정(type-plan 권한 유지).**
- 유형 목표와 묶음별 쿼터는 계속 `type-plan.ts`가 정함.
- `assignUnitsToSlots`가 묶음 순서대로, 묶음 안에서는 이미지 → 임상 → 지식 → free 칸 순으로 유형이 맞는 단위를 앞에서부터 넣음.
- 맞는 단위가 없으면 아무 단위나 넣고 '불일치'로 셈.
- 칸에 들어가지 않은 단위는 예비(D3)임.

**폴백.** 계획 콜이 실패하면 현행 `extractFocusTopics()` 초점을 주제·질의로 쓴 단위로 대신함.

**HyDE.** 가상 발문은 검색에만 쓰고 생성 입력에는 넣지 않음(5.2 D).

## 2. 평가 방법

골든셋 10건 × 2회를 돌림. 요청 조건은 다음과 같음.
- 10문항, 지식형+임상형, 난이도 중
- IM1은 이미지형을 포함하고 캡션 10개를 넣음. 캡션은 PR F `caption-eval` 결과를 씀.

단위 검색은 E1~E3 확정 구성 그대로임: voyage-4 dense, 질의 4개 각 top-20 → RRF → 근거 팩 6. 비교 기준(현행)은 `extractFocusTopics` 초점(자료당 최대 24개)을 주제 하나짜리 질의로 쓴 것임. 초점이 계획 단위(15개)보다 많아 현행에 유리한 비교임.

**판정 기준은 실행 전에 적어 둠.** P2·P3·P4 중 하나라도 미달이면 프롬프트를 1회만 고쳐 다시 재고, 고치기 전 결과도 남기기로 함.

| # | 항목 | 기준 |
|---|---|---|
| P1 | 형식 | 유효 계획 ≥ 19/20, 실행마다 단위 10~17개 |
| P2 | R1 일치 | R1 단위 중 어떤 계획 단위의 1위 청크가 그 정답 인용구를 담은 비율이 현행 초점보다 낮지 않음 |
| P3 | 근거 충분 | 단위 최고 유사도 ≥ τ(0.61) 비율 ≥ 0.90 |
| P4 | 중복 | 1위 청크가 다른 단위와 겹치지 않는 단위 비율 ≥ 0.80 |
| P5 | 원가·지연 | 계획 콜 1회 ≤ $0.02, 지연 p95 ≤ 20초 |

## 4. 수정 내용 (1회, P3·P4 미달 후)

1차에서 P3(0.863)와 P4(0.733)가 미달이었음. 다음 세 가지를 한 번에 고침.

1. **요약 확장.** 페이지 요약을 '제목 + 첫 2문장'(최대 220자)에서 '제목 + 상한 안의 첫 문장들'(최대 600자)로 늘림. 12,000자 상한을 페이지 수로 나눠 씀. 1차 입력은 최대 4.5k 토큰으로 상한의 절반 아래였음.
2. **검색어 지시.** 검색어에 그 단위가 짚은 쪽 요약의 단어를 그대로 넣어 구체적 사실 하나를 겨냥하게 함. 여러 주제 나열을 금지하고, HyDE 발문은 60자 이내로 함.
3. **단위 수.** 자료가 짧아 근거가 겹치지 않는 단위를 다 못 만들면 요청 수까지 줄여도 된다고 적음.

결과는 다음과 같음.
- P4는 0.871로 충족함.
- P2는 0.399에서 0.523으로 올랐음.
- P3는 0.861로 그대로임. τ 아래 단위가 짚은 쪽을 1위로 찾은 비율은 28/41에서 39/42로 올랐음.
- 3번 지시는 효과가 없었음. 9쪽짜리 NT2에서도 모델은 15개를 만들었음.

## 5. 약어 사전 (5.2 D) — 넣지 않음

**시드 후보를 살펴본 결과**
- 자체 문항 `concepts`(2,608문항, 3,552개)에는 약어–풀이 쌍이 거의 없음. 약어꼴 31개는 풀이가 없고, 괄호꼴 13개 중 동의어 쌍은 '콩팥증후군(신증후군)' 같은 몇 개뿐임.
- CPX 신체진찰 온톨로지 alias(931개)는 진찰 행동 표현이라 강의 주제와 거의 겹치지 않음.

**실험**
- 시드 대신 자료 안 정의(`LES (lower esophageal sphincter)`, `하부식도괄약근(LES)`)를 뽑아 R1 정답 질의를 넓혀 봄.
- 자료당 정의 1~17개, 질의 596개 중 110개가 바뀌었음.
- Recall@6: 전체 0.970 → 0.970, 검토 59단위 0.983 → 0.983, 자료별 변화 0.

voyage-4 dense가 이미 한·영 약어를 잘 잇고 있어(E1~E3 천장 효과) 사전 기준(+0.01)을 넘을 여지가 없었음. E5에서 약어 때문에 놓친 근거가 보이면 다시 봄.

## 6. 운영 경로 확인

골든셋 하네스로 이 브랜치를 운영 DB에 붙여 shadow로 1회씩 돌림. 텍스트 자료 SL1과 이미지형을 포함한 IM1임. 테스트 업로드는 지움.

- **SL1의 원가 교차 검증은 −16%로 미달임.** 원인은 생성 비용 행 하나가 Supabase 522(연결 시간 초과)로 `ai_cost_log`에 들어가지 못한 것임. 진단 안의 귀속 합계와 파이프라인 합계는 $0.232128로 같았고, IM1은 0.35%로 통과함.

## 7. 한계

- **R1 일치는 하한 지표임.** R1 단위도 LLM 초안이고(사람 검토 59/149), '정답 계획'이 아님. 계획이 R1에 없는 좋은 단위를 만들어도 점수가 오르지 않음. 1위 청크 기준이라 엄격함.
- **생성 품질은 아직 재지 않음.** 단위가 문항 품질·중복·커버리지에 주는 효과는 PR I 이후 E5에서 G1 지표로 봄.
- **제공자 과부하.** 수정 후 첫 실행에서 gemini-2.5-flash 503(수요 과다)으로 20회 중 10회가 폴백됐음.
  - 503·429만 30초 간격으로 다시 부르게 하고 전부 다시 돌림(재시도 0회로 끝남). 첫 실행 기록도 보관함.
  - 운영에서 같은 일이 생기면 계획 콜만 폴백되고 생성은 영향이 없음(shadow).
- **스캔 자료(SC1).** 본문이 거의 없어(F11) 계획이 성기고 근거 충분 비율이 낮음. 스캔 쪽 OCR 정책은 이번 범위 밖임.
