# E1~E3·E2 검색 구성 확정 (RAG 실행계획 v1.1 · 6.3 · G0 '검색 품질')

2026-09-28 · 전재현 · 도구: `scripts/rag-eval/`(#278) · 적용: `lib/rag/mode.ts`의 `RAG_DEFAULTS`(PR D)

## 결론

- **임베딩 voyage-4 + dense 단독, sparse·리랭커 없음, 1,200자 청크 단독(부모 확장 없음), τ 0.61.**
  - *2026-10-05 추가: τ 0.61 은 R1 질의(정답 청크를 보고 쓴 질의) 기준이다. 운영 질의(계획 콜이 요약만 보고 씀) 기준으로는 PR H 에서 0.47 로 다시 정했다([h-pack-results.md](h-pack-results.md)). 이 문서의 판정은 바뀌지 않는다.*
- 사람 검토 라벨에서 voyage-4의 Recall@6은 0.983임. G0 기준 0.80을 넘어 **G0 6개 항목이 모두 충족됨.**
- 운영에 Voyage 키를 되살려야 함(F7). 리랭커를 쓰지 않으므로 필요한 외부 키는 Voyage 하나임.
- 한계: R1 라벨 149단위 중 사람이 확인한 것은 59단위(40%)임. 나머지 90단위는 LLM 초안과 교차검증 결과만 있는 상태임. 두 집합의 판정이 같은 구성을 가리켜서 확정했음(3장).

## 3. 사전 판정 기준 적용 (6.3)

| 실험 | 기준 | 검토 59단위 | 전체 149단위 | 결정 |
|---|---|---|---|---|
| E1 임베딩 | Recall@6 최고를 채택하고, 0.03 이내면 ① 새로 살릴 키 수 ② 단가 순 | voyage-4가 gemini보다 +0.042 높아 단독 1위 | 0.009 차이로 동률 → ①은 E3 결과와 합쳐 둘 다 Voyage 키 1개(아래) → ② voyage-4가 더 쌈($0.06 vs $0.20 /1M) | **voyage-4** |
| E3 sparse | RRF가 dense보다 0.01 넘게 손해면 불채택 | −0.017 | −0.026 | **불채택** |
| E3 리랭커 | +0.03 이상이고 p95 증가 1.5초 이하일 때만 채택 | +0.009 | +0.027 | **불채택** |
| E2 청킹 | Recall 최고를 고르고, 0.02 이내면 토큰이 적은 쪽 | 셋 다 같음 | 셋 다 같음 | **a. 1,200자 단독** |
| τ | 단위 최고 점수 분포에서 Recall 0.9를 남기는 가장 높은 값 | 0.626 | 0.607 | **0.61** |

- **전체 149단위에서 E1 ①을 따질 때 가능한 조합.**
  - voyage-4 dense 단독: 리랭커 기준에 미달해 리랭커를 붙이지 않음. Voyage 키 필요.
  - gemini-embedding-2 + rerank-2.5: 이 조합에서는 리랭커 이득이 +0.036으로 기준을 넘음. 리랭커 때문에 Voyage 키 필요.
  - 두 조합 모두 새로 살릴 키는 Voyage 하나라 ①로는 갈리지 않음. ② 단가에서 voyage-4 단독이 쌈.
- **PR E 설명의 예비 판정과 달라진 이유.** 그때는 E1 동률을 가를 때 리랭커가 요구하는 Voyage 키를 빼고 셌음. 계획서 문구대로 E3와 합쳐서 판정하면 위와 같이 voyage-4가 됨.
- **천장 효과.** 거의 모든 구성이 0.94~1.00에 모여 있음. 질의와 근거를 같은 LLM 계열이 같은 자료를 보고 만들어 생긴 낙관 편향일 수 있음. Phase 1에서는 출제 계획 콜이 질의를 만들기 때문에 같은 조건일 가능성이 높지만, E5에서 실제 문항 기준 근거 충실도로 다시 확인함.

## 4. 원가·운영 영향

- **임베딩 비용.** voyage-4 $0.06/1M 토큰 기준, 자료 1건(청크 50개 안팎, 약 1.5만 토큰)을 인덱싱하는 데 약 $0.001임. 문항당 원가 기준선 $0.0241 대비 0.5% 수준임.
- **질의 임베딩.** 단위당 질의 4개로, 한 업로드에 15단위면 60건임. 비용은 무시할 수 있는 수준임.
- **운영 키.** 운영 Voyage 키는 2026-07-21 이후 죽어 있음(F7). `shadow`로 바꾸기 전에 Vercel의 `VOYAGE_API_KEY`를 유효한 키로 바꿔야 함. 키가 죽은 채로 `shadow`를 켜면 인덱싱만 실패하고(진단 경고), 생성은 영향이 없음.
- **설계 변경.** 5.3 스케치에서 HNSW·pg_trgm 인덱스를 뺐음(00045 머리말). 5.2 E·F의 하이브리드 검색·리랭크 단계는 dense 단독으로 단순해짐.
