그래프 RAG — 지식 그래프 추출 + 서브그래프 템플릿 출제 + 구조적 오답 생성

자료를 청크 집합이 아니라 지식 그래프(질환–증상–검사–소견–치료–기전–해부–이미지)로 바꾸고, 문항 유형별 서브그래프 템플릿으로 근거를 모은다. 오답을 형제 노드(감별 진단·같은 계열 약물)에서 구조적으로 생성하고 그래프 커버리지로 출제 분포를 관리한다. 출제 품질의 상한은 가장 높지만, 추출·정규화 비용과 평가 난이도도 가장 크다.

2핵심 메커니즘

스키마 (초안)

노드 8종Disease · SymptomSign · Test · Finding · Treatment/Drug · Mechanism · Anatomy · Image 관계 10종presents_with · diagnosed_by · finding_of · treated_with · contraindicated · mechanism · differential_of · complication_of · risk_factor · depicted_in 모든 edgeevidence_chunk_ids[] · confidence · origin(material | external)

서브그래프 템플릿 → 문항 블루프린트

  • 진단형 질환 + presents_with 3~4 + diagnosed_by 1 / 오답 = differential_of
  • 치료형 질환 + treated_with + contraindicated / 오답 = 같은 계열 다른 약물
  • 기전형 질환 + mechanism + anatomy / 오답 = 인접 기전
  • 이미지형 Image –depicted_in→ Finding –finding_of→ Test

구조적 오답 생성

정답과 증상을 2개 이상 공유하되 결정적 소견이 다른 노드를 우선 → 방어 가능하면서 그럴듯한 오답. 정답과의 거리(hop·임베딩)로 난이도를 조절하고, 오답 관계가 그래프에 실제로 없는지 코드가 검사한다.

커버리지 · 개인화 기반

출제된 노드·edge를 kg_coverage에 기록해 다음 요청에서 미출제 영역을 우선. 학생의 오답을 노드에 귀속시키면 "약한 개념"이 그래프 위에 정의되어 개인화(현재는 누적 오답률 집계뿐)로 확장된다. 기존 유휴 자산 physical_exam_ontology.json(156개념·931 alias)을 시드로 재활용.

3예시 서브그래프 — 진단형 문항

진단형 템플릿: 중심 질환 + presents_with 3개 + diagnosed_by 1개가 발문·정답 근거, differential_of 노드가 오답 후보, depicted_in 이미지가 붙으면 이미지 문항으로 성립. 해설은 경로 설명.

5장점

  • 오답이 구조적으로 생성 — 정답 길이 누출·위치 편중 같은 통계 결함을 근본에서 완화
  • 해설이 경로 설명이 되어 교육적 가치 상승
  • 출처가 edge 단위로 보존 — 근거 추적의 최고 해상도
  • 유형 편중(치료 28% · 기전 2%)과 커버리지를 그래프 분포로 제어
  • 여러 자료·CPX 증례를 한 그래프로 통합 → 개인화·과목 단위 학습 기반

6단점 · 위험

  • 추출·정규화 비용과 지연이 가장 큼 (청크당 1콜)
  • 추출 오류(관계 방향·과잉 일반화, 문헌상 정밀도 70~85%)가 누적되면 문항 전체 오염
  • 그래프 품질 평가에 전문가 시간이 가장 많이 듦 · 스키마 설계가 온톨로지 전문성 요구
  • 슬라이드형 자료는 문장이 짧아 관계 추출이 빈약할 수 있음
  • 저작권 제약(교과서·용어집 추출원 제외) · 자료 자체의 오류를 구조화할 위험
