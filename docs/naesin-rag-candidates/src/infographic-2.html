자가교정형 RAG — 검색 평가기 + 생성 비평기 + 수정 루프 (CRAG × Self-RAG)

2핵심 메커니즘

검색 평가기의 3등급과 행동

top-1 리랭크 점수 ≥ τ_hi 이고 LLM 판정 "충분"이면 CORRECT, < τ_lo 또는 "무관"이면 INCORRECT, 사이는 AMBIGUOUS. 원 CRAG의 웹 검색 보정은 자료 기반 원칙 때문에 쓰지 않고 "출제 단위 포기"를 택한다(외부 교과 지식 보정 허용 여부는 Q6).

비평기 4축 스키마

  • IsSupported — 주장별 supported + evidence_id + quote
  • IsCorrect — severity(none/minor/major/critical) + rationale + quote 또는 "자료 밖 지식" 표기
  • IsUnique — 오답 4개 방어 가능성, 복수 정답 여부
  • IsUseful — 코드 린트(F·K·C) 결과를 입력으로

생성기 ≠ 비평기

1차안: 생성 gemini-2.5-flash / 비평 claude-haiku-4-5 또는 gemini-2.5-pro. 벤더를 달리하면 상관 오류가 줄지만 키·비용 관리가 는다. 비평기 2종 합의(2-of-2) 차단은 오탐을 더 줄이되 비용 2배 — 골든셋 오탐/미탐 곡선으로 결정.

오탐 억제 · 루프 중단

현행 P1의 "자가당착 오탐"(지적이 문항과 무관)을 막기 위해 모든 critical/major 지적은 quote를 동반해야 하며 코드가 quote를 찾지 못하면 minor로 강등. 루프는 최대 2회, 점수 미개선 시 즉시 중단, 업로드당 추가 콜 상한 = 문항 수 × 3.

4장점

  • 문항 단위 품질 보증 — "의학 정확성 방어선 0"을 없애는 유일한 후보
  • 비평 기록이 전문가 검수(C4)·표본 추출(A12)에 직접 쓰임
  • 가이드의 "중대/경미 오류율" 조작적 정의를 코드에 심을 수 있음
  • 검색 실패를 "근거 부족"으로 정직하게 알림 (억지 출제 감소)
  • 후보 1 위에 레이어로 얹혀 점진 도입·롤백이 쉬움

5단점 · 위험

  • 비용 약 2배, 지연 +15~30초
  • 루프로 인한 비결정성 → 반복 안정성 지표 악화 가능
  • 비평기 편향(보수적 → 미탐 / 공격적 → 오탐)을 전문가 라벨로 보정해야 함
  • "자료 밖 표준 지식"과 "자료 내 근거"를 혼동해 정확한 문항을 거부할 수 있음
  • 차단 모드 전환 시 문항 수 부족 → 보충 라운드 의존 증가

7교수님께 여쭙는 점

  1. 비평기 스키마에 심을 중대/경미 오류 분류(C1) — "정답이 바뀌면 중대, 해설 표현 오류는 경미"로 충분한지
  2. 생성기·비평기 벤더 분리의 실익을 검증할 실험 설계(상관 오류 측정)
  3. "자료 근거 부족" 시 단위 포기 vs 표준 교과 지식 보정 — 교육적·저작권적 타당성
  4. 루프 중단 기준(2회·점수 미개선)과 차단 임계의 보정에 필요한 라벨 규모
