## 1. 사전 판정 기준 (실험·구현 전 기록, 2026-10-05)

**J1 중복 보정 (오프라인, 모델 생성 없음)**

- 자료: 골든셋 문항 — G0 off 300(10건 × 3회) + i-on 100 + i-on-2 99 + i-on-im 20. 같은 자료 안의 모든 쌍(같은 실행 안 + 실행 간)
- 임베딩: voyage-4(document). 입력 후보는 (a) 발문 (b) 발문 + 정답 선지 (c) 발문 + 선지 5개
- 라벨: LLM(gemini-2.5-flash, temperature 0)
  - "중복" 정의: 같은 개념·사실을 같은 방향으로 묻고 정답의 근거가 같아, 하나를 풀면 다른 하나의 답을 바로 아는 경우
  - 라벨 대상: 세 입력 중 하나라도 코사인 ≥ 0.80인 쌍 전부(최대 600, 넘으면 구간별 층화) + 0.70~0.80 구간 무작위 80쌍(재현율 추정용)
  - 의학 전문가 라벨이 아님
- 판정
  - 입력: ROC-AUC가 가장 높은 것(차이 0.02 이내면 짧은 입력)
  - 임계: 정밀도 ≥ 0.90을 만족하는 가장 낮은 값(0.85~0.98, 0.01 간격). 없으면 0.98
  - G1의 '중복 문항률' 정의(코사인 ≥ 0.92)는 그대로 두고, 폐기 임계만 이 값을 씀
- 함께 보고: G0 off의 세트 안 중복률·실행 간 중복률(기준선)

**J2 유형 수확 — 묶음 재생 실험**

- 수집: on 1회 × 4건(SL3·SC1·NT2·IM1 — i-on·i-on-2에서 임상형·이미지형 수확이 낮았던 자료)에서 본 묶음의 첫 생성 요청 원문을 저장함
- 재생: 같은 요청을 지시만 바꿔 다시 보냄(묶음 × 변형 × 2회)
  - V0 = 수집 그대로(PR I 인용 지시)
  - V1 = 칸 유형별 인용 지시
    - 그림 판독 칸: 소견은 그림에서, 그 의미의 근거는 자료에서
    - 임상 증례형 칸: 환자 증례(나이·성별·주소·소견)로 지문을 만들고 진단·치료·다음 검사 등을 물음. 환자 정보는 지어도 되고, 정답을 가르는 소견·수치·기준은 근거 자료에서 가져와 인용함
- 지표: 묶음 첫 응답의 임상 쿼터 충족(Σ min(증례형, 쿼터) / Σ 쿼터, `isClinicalVignette`), 엄격 인용 통과율, 이미지 묶음 그림 부착
- 채택: V1이 임상 쿼터 충족을 +0.10 이상 올리고 엄격 인용 통과율 하락이 0.05 이하이면 채택함. 아니면 V0을 유지하고 이월로 기록함

**구조 변경(실험 없이 넣고 J3에서 확인)**

- D3: 교체 뒤에도 단위가 없는 칸은 만들지 않고(보충도 하지 않음) `insufficient_evidence`로 알림. 유형 목표는 남은 칸 기준

**J3 최종 실행** (on, 골든셋 10건 × 1회, G0와 같은 요청 조건. 코드가 PR K까지 그대로면 E5 on 1회차로 재사용함)

- PR I의 I1~I8을 다시 충족(I2는 `insufficient_evidence`로 설명되는 부족분 제외)
- 세트 안 중복률(코사인 ≥ 0.92, J1 입력) ≤ 2% (G1)
- 세트 간 중복 시험: SL1을 같은 계정에서 2회 연속 실행(두 번째는 첫 번째 문항이 남은 상태). 두 번째 세트가 첫 세트와 겹치는 문항(코사인 ≥ 폐기 임계) 0건

미달 시 항목당 1회만 수정·재실행하고, 수정 전 결과를 남김.

- 문항 임베딩 116개(보충 문항 포함), 비용 $0.00067(10회 합). 세트 안 폐기 1건(SL4), 세트 간 0건

**그 밖의 보고**

- D3: 골든셋 유효 실행에서는 근거 부족 칸이 없었음(slotsWithoutUnit 0). 무효가 된 실행 1건에서 1칸이 발동해 알림 경로가 돈 것은 확인함. 동작은 단위 검사(`check:rag-dedup`)로 덮음
- 검증기 경고율 0.465(53/114, G0 0.371, j-on 0.420). on에서 꾸준히 높음 → PR K에서 사유 분석
- 생성 호출 실행당 8.7회(교정 17, 인용 교정 1), 근거 대기 중앙값 15초
- 운영 사고 기록: 2026-10-05 13시~10-06 07시(UTC) 사이 gemini-2.5-flash가 3천 토큰 이상 요청에 `429 RESOURCE_EXHAUSTED`(할당량 정보 없음)를 돌려줌. 크레딧(잔액 있음)·프로젝트 할당량(분당 100만 토큰 중 3%)과 무관했고, 같은 키의 2.5 Flash Lite·3.8 Flash는 정상이었음. 하네스가 무효 처리한 실행 5건(전부 SL1, $0.15)은 업로드를 지우고 기록만 따로 둠. 운영 코드(`lib/ai/client.ts`)는 이 응답을 크레딧·쿼터 소진으로 보고 재시도하지 않음 → 일시적 용량 부족에서도 묶음이 바로 실패함(별도 수정 제안)

**이월(PR K·E 단계)**

- 이미지형 수확: 그림 판독 칸의 발문이 그림 없이 풀리는 문제(블라인드 탈락). E5에서 이미지 칸 지시·블라인드 기준을 함께 봄
- 임상형 회복 여부는 E5 3회로 판정
- 인용 임계(0.90)·8자 하한은 E4에서 다시 정함. 관대 기준이라 E4는 '저장 인용의 정확도'와 '틀린 인용을 뗀 문항의 근거 충분성'을 같이 봐야 함
- 넓은 의미의 중복(임베딩 재현율 0.44)은 출제 단위 배정과 P11이 맡음 — G1은 계속 계측
- 코드가 PR K까지 그대로면 j-on2를 E5 on 1회차로 재사용

## 5. 구현

| 단계 | 내용 | 위치 |
|---|---|---|
| 문항 임베딩 | 저장 직후·보충 라운드마다 새 문항만 voyage-4로 임베딩(`rag.question`, 원가 반영) → `private_questions.embedding`·`embedding_model` | PG `enforceSetDuplicates` |
| 세트 안 중복 | slot 순으로 앞 문항과 코사인 ≥ 0.93이면 뒤 문항이 중복. 지운 문항은 비교 기준에서 빠짐 | `lib/rag/dedup.ts` |
| 세트 간 중복 | 같은 사용자·같은 `content_sha256`의 다른 업로드 문항과 `match_private_questions`(≥ 0.93)로 비교, 문항마다 한 번 | PG |
| 폐기 | on만 지우고 보충이 채움. shadow는 진단(`generation.dedup`)만. off는 아무것도 안 함(비용 0) | PG |
| G1 계측 | 남은 세트의 세트 안 중복률(≥ 0.92)을 진단 `dedup.g1`에 남김 | PG |
| 검색 스냅샷 | `source_refs.retrieval = {embed, k, fusion, reranker, topN, mmr, tau}` | `lib/rag/mode.ts` `retrievalRefSnapshot` |
| D3 | 교체 뒤에도 단위가 없는 칸은 생성·보충에서 빼고 쿼터를 줄임. 칸이 전부 근거 부족이면 현행 경로로(`no_sufficient_units`). 알림 `insufficient_evidence`(화면 문구 포함) | PG, `lib/rag/evidence.ts`, `upload-notice.ts` |
| 유형 재계산 | 유형 목표 = 남은 칸 수 기준. 보충 칸은 부족 유형에 맞는 예비 단위를 먼저 고름 | `backfillSlotInputs` |
| 이미지 칸 | 이미지 정제를 근거 대기와 겹쳐 미리 돌리고, 칸마다 쓸 수 있는 서로 다른 그림의 단위를 고름 | `assignImageSlots` |
| 인용 지시 | 본문을 `prompts/rag-cite-directive.ts`로 옮김(V0 글자 그대로). J2에 따라 V0 유지(`RAG_CITE_ACTIVE = 'v0'`) | |
| 인용 판정 | 문항은 관대 기준(맞는 인용 1개 이상)으로 남기고 틀린 인용은 저장하지 않음. 교정 재생성 대상도 같은 기준. 진단 `citeRefsDropped` | `lib/rag/cite.ts` `citationAccepted`, PG |
