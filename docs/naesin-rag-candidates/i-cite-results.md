# 5.2 G·H·I 인용 강제 생성·인용 검증·검증기 입력 교체 결과 (RAG 실행계획 v1.1 · PR I)

2026-10-05 · 전재현 · 도구: `scripts/rag-eval/cite-eval.ts` · 적용: `lib/rag/cite.ts`, `lib/rag/evidence.ts`, `lib/ai/private-generation.ts`

## 결론

- **on에서 생성이 근거 팩을 쓰게 바꿈.** 묶음마다 그 칸 단위들의 근거 팩만 주고, 문항마다 `evidence_refs`(근거 번호 + 원문 구절)를 필수로 받음. 코드가 구절을 원문과 대조해 틀리면 1회 교정, 그래도 틀리면 버리고 보충함. 검증기는 그 문항의 근거 팩을 받고, 출처 쪽은 인용 청크에서 파생함. off·shadow 생성은 그대로임(소스 대조 + 가짜 Gemini 배선 시험).
- **사전 기준 I1~I8을 모두 충족함**(골든셋 10건 × on 1회, 4장)
  - 근거 경로 10/10, 제공 100/100, 저장 문항 100%가 원문과 다시 대조해도 맞는 인용을 가짐(인용 237개)
  - 첫 응답 인용 통과율 0.892, 교정 뒤 폐기 1.4%
  - 문항당 원가 중앙값 $0.0267(기준선 $0.0241, 상한 $0.0362), 처리 시간 p95 152초(상한 219초), 형식 위반율 32%(G0 28~34%)
- **원가는 줄지 않고 11% 늘었음.** 생성 사용자 메시지의 약 85%(SL1 배선 시험 기준)가 자료가 아니라 분류 카탈로그라 근거 팩이 줄인 입력은 호출당 4%뿐이고, 인용 교정 호출(10회당 1.2회)이 더해짐. 카탈로그 축소가 원가를 줄일 실제 지렛대임(PR J·K에서 다룸).
- **처리 시간 중앙값이 51초 → 87초로 늘었음.** on은 선발사를 끄고 근거(계획 콜 포함)를 15~39초 기다림. p95는 상한 안임.
- **사전 기준 밖에서 유형 수확이 떨어짐 — PR J로 넘김**
  - 임상형: 저장/목표 0.816(G0 0.925). 묶음 첫 응답의 임상 쿼터 충족 0.415(G0 0.629)
  - 이미지형(IM1): 1문항(목표 3, G0 3·3·3). 블라인드 재작성이 5회 중 0회 성공
  - 원인은 "근거 자료로 뒷받침할 수 없는 내용을 정답·조건으로 쓰지 말 것"이라는 인용 지시가 이미지 규칙("그림에서만 읽히는 소견으로 정답을 가를 것")·증례 서술과 부딪히는 것으로 봄
  - 사후 수정 두 가지(그림 판독 예외, 임상 증례 예외)를 시험했지만 미리 적은 해소 기준(이미지 평균 ≥ 3, 임상 ≥ 0.90)에 못 미쳤고, 두 수정을 함께 넣은 재실행에서는 I5(폐기율)가 6.0%로 기준을 넘음. 그래서 **PR I에는 사전 기준을 통과한 코드만 넣고**, 두 수정과 결과는 PR J의 출발점으로 남김(5장)
- **검증기 경고율은 0.448(G0 0.371).** 경고 내용 구성(근거 없음 9% 등)은 off와 비슷함. 근거 팩 입력 때문에 '근거 없음' 판정이 늘지는 않았음. 같은 날 고친 해설 번호 버그(별도 PR)와 무관하게 검증기 경고는 원래 잡음이 큼.

## 1. 사전 판정 기준 (구현·실행 전 기록, 2026-10-05)

범위: `PRIVATE_RAG_MODE=on`에서만 생성이 바뀜. off·shadow는 생성 불변(`check:rag-cite` 소스 대조).

**구현 규칙(실행 전 고정)**

- 생성 입력은 묶음 칸에 배정된 단위(D3 교체 반영)의 근거 팩 합집합임. 청크 중복을 없애고 `[E1]…` 번호를 새로 붙이며, 단위 목록(주제·목표·근거 번호·칸 유형)을 문항 순서대로 붙임. HyDE 발문은 넣지 않음. 칸에 맞는 단위가 없으면(D3 부족) 교체 전 단위의 팩을 쓰고 진단에 남김. 부족 알림과 '적게 제공'은 PR J에서 함.
- 도구 스키마에 `evidence_refs: [{id, quote}]`를 필수(1~3개)로 둠. `source_pages`는 스키마에서 빼고 인용 청크의 쪽으로 파생함.
- 인용 검증(코드, LLM 0콜)
  - 정규화: NFKC → 소문자 → 따옴표·대시·가운뎃점 통일 → 공백 전부 제거
  - 부분 일치율 = 1 − (quote를 청크의 어떤 부분 문자열로 바꾸는 최소 편집 거리 / quote 길이). 대상 청크 글은 모델에게 실제로 보인 글(팩에 잘려 담겼으면 잘린 글)임. 임계 0.90
  - 정규화 후 8자 미만 quote는 불합격
  - 같은 묶음의 다른 근거에서 일치하면 그 근거로 바로잡음(재귀속, 진단 집계)
  - 문항 판정은 엄격: 인용 1개 이상 + 모든 인용 합격. 관대 기준(합격 인용 1개 이상)의 통과 수도 같이 셈
- 불합격 문항이 있으면 묶음당 1회 교정 재생성함. 합격한 새 문항으로 빈자리만 채우고, 못 채운 자리는 폐기 → 보충. 이후 교정 재생성(이미지·난이도·블라인드) 결과도 같은 검사를 거침(통과 못 하면 버림, 추가 재생성 없음).
- 검증기 `sourceText`는 그 문항의 근거임(인용 청크가 가장 많이 속한 단위의 팩 + 팩 밖 인용 청크).
- 교정 재생성은 같은 메시지(= 근거 팩)를 다시 보냄. 전체 컨텍스트 재전송 없음(F5).
- 근거 준비(계획·인덱싱·검색)가 45초 안에 안 끝나거나 실패하면 현행 full-context 경로로 폴백하고 사유를 진단에 남김.
- on에서는 텍스트 선발사를 끔(생성이 근거를 기다려야 함).

**실행.** 골든셋 10건 × on 1회. 요청 조건은 G0와 같음(10문항, 난이도 중, 지식+임상, IM1은 이미지형 포함). 기준선은 G0 off 3회([g0-baseline.md](g0-baseline.md)). 운영 DB·테스트 계정으로 돌리고 끝나면 하네스 업로드를 삭제함.

**판정 기준 (PR I 병합 판단용. `on` 전환 판단은 G1·E5에서 따로 함)**

| # | 항목 | 기준 |
|---|---|---|
| I1 | 근거 경로 진입 | 10/10 업로드가 폴백 없이 근거 팩으로 생성(인프라 오류는 사유와 함께 따로 기록) |
| I2 | 제공 문항 수 | 실행당 저장/요청 평균 ≥ 0.95 |
| I3 | 인용 불변식 | 저장 문항 100%가 코드 검사를 통과한 인용 1개 이상을 가짐(배선 확인) |

| I6 | 문항당 원가 중앙값 | ≤ $0.0362 (기준선 × 1.5) |
