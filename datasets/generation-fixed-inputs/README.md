# 문항 생성 반복 안정성 — 고정 입력셋 (분담표 A3)

같은 자료·같은 프롬프트·같은 모델로 N회 생성해 변동을 재는 데 쓰는 **테스트셋**이다.
가이드 §4.2는 최소 10회 반복을 요구한다.

```bash
npm run check:gen-repeat -- --list                       # 등록된 고정 입력
npm run check:gen-repeat -- --selftest                    # 산식만 (API 키 불필요)
ANTHROPIC_API_KEY=... npm run check:gen-repeat -- --runs 10 --fixture seed-acs-v1
```

## 이 파일들은 테스트셋이다

결과를 보고 프롬프트를 고친 뒤 **같은 입력으로 다시 재면 그 수치는 개발셋 성능**이지
테스트셋 성능이 아니다(가이드 §10.2). 입력을 바꾸면 이전 측정치와 비교할 수 없으므로,
바꿔야 하면 새 `id`로 등록한다.

갖춰지면 `datasets/manifest.json`의 `generation-fixed-inputs-v1`을 봉인한다:

```bash
npm run check:datasets -- --lock generation-fixed-inputs-v1
```

## 형식

`<id>.json` 하나가 고정 입력 하나다.

```json
{
  "id": "cardio-acs-v1",
  "subject": "순환기",
  "description": "무엇에서 뽑은 자료인지",
  "desiredCount": 10,
  "style": "kmle",
  "subTopicCatalog": [{ "code": "CV-ACS", "name": "급성 관상동맥 증후군", "subject_name": "순환기" }],
  "topic": "선택 — 출제 초점",
  "keywords": ["선택", "핵심 키워드"],
  "sourceText": "강의자료에서 추출된 텍스트 전문"
}
```

`sourceText`는 **추출 단계를 거친 뒤의 텍스트**를 넣는다. 하니스는 업로드·OCR을 다시
돌리지 않고 생성 호출만 반복한다 — 재려는 것이 생성의 변동이지 추출의 변동이 아니기 때문이다.

## 층화 구성 (20–30건 목표)

한 과목·한 형식만 모으면 그 조건에서의 안정성만 알게 된다. 아래를 섞는다.

| 축 | 섞을 것 |
|---|---|
| 과목 | 최소 5개 과목 |
| 자료 형식 | 텍스트 위주 / 표·수치 많은 자료 / 그림 설명 많은 자료 |
| 분량 | 짧은 자료(1–2천자) / 긴 자료(1만자 이상) |
| 요청 난이도 | 하 / 중 / 상 |
| 요청 문항 수 | 5 / 10 / 20 |

## 지금 있는 것

- `seed-acs-v1` — **시드 1건.** 하니스가 도는지 확인하는 용도로 직접 작성한 텍스트다.
  실제 강의자료가 아니고 표본도 1건이라, **이것으로 낸 수치를 성능 주장으로 쓰지 않는다.**

실제 20–30건은 강의자료가 있어야 하는 작업이다. 원본 자료 자체를 저장소에 넣기 어려우면
추출 텍스트만 넣고 출처는 `description`에 적는다.

## 무엇을 판정하는가

하니스는 두 층을 나눠 본다.

**계약 (합격/불합격)** — 여기서 흔들리면 버그다.
- 스키마 준수율 (필수 필드·자료형·범위)
- 요청한 문항 수와 일치
- 한 실행 안에 중복 문항 없음
- 전 실행 성공

**분포 (보고만)** — 매번 다른 문항이 나오는 것은 정상이다.
- 실행 간 문항 겹침 — 1에 가까우면 재생성이 새 문항을 못 만든다는 신호
- 개념 Jaccard, 관측 개념 수
- 난이도 분포, KMLE 형식 규격 위반율
- 실행시간 p50/p95
