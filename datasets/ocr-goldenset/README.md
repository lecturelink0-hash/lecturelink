# OCR 골든셋 — 전사 작업 안내 (분담표 A5)

측정기(`scripts/eval-ocr.mjs`)는 이미 있다. **없는 것은 정확한 원문 전사뿐**이고,
그것만 채우면 그날 바로 CER·WER 수치가 나온다. 전사는 전문의 판단이 필요 없으므로
2인이 직접 하는 작업이다.

## 왜 층화가 중요한가

가장 흔한 실패는 "잘 나온 표본만 모으는 것"이다. 쉬운 텍스트 슬라이드만 100장 모으면
CER이 낮게 나오고, **그 수치는 실제 강의자료에서 재현되지 않는다.** 그래서 구성 비율을
`composition.json`에 박아 두고 `scripts/check-ocr-goldenset.mjs`가 강제한다 —
사람의 의지가 아니라 도구로.

| 갈래 | 목표 비율 | 왜 필요한가 |
|---|---|---|
| 일반 텍스트 슬라이드 | 30–45% | 기준선. 이것만으로는 실제 성능을 대표하지 못한다 |
| 표 | 15–30% | 행·열이 무너지면 수치가 엉뚱한 항목에 붙는다 |
| 그래프·도표 | 10–25% | 축 라벨·범례만 텍스트라 본문과 난이도가 다르다 |
| 손글씨·판서 | 8–20% | 실제 업로드에 섞여 온다. 빼면 CER이 실제보다 좋게 나온다 |
| 임상 이미지 텍스트 | 5–20% | 저대비·회전·작은 글씨 — 의료 자료 특유의 실패 모드 |

목표 총량 **100–150장**.

## 파일 규약

```
datasets/ocr-goldenset/
  samples.csv        # 대장 — 여기에 먼저 등록한다
  001.png            # 원본 이미지 (git 에는 올리지 않는다)
  001.txt            # 사람이 만든 정답 전사
  002.png
  002.txt
```

**이미지는 저장소에 올리지 않는다.** 강의자료라 저작권·개인정보 문제가 있다.
`.gitignore`가 막고 있으며, 전사(`.txt`)와 대장(`samples.csv`)만 버전 관리한다.
이미지는 별도 보관소에서 받아 이 디렉터리에 놓고 측정한다.

`samples.csv` 열: `id,stratum,source,transcribed,notes`

- `id` — 파일 이름과 같게 (`001` → `001.png`/`001.txt`)
- `stratum` — `composition.json`의 갈래 id (`slide-text`·`table`·`figure`·`handwriting`·`clinical-image`)
- `source` — 어느 강의자료 몇 페이지에서 왔는지. 비워도 통과하지만 경고가 뜬다
- `transcribed` — 전사 완료면 `y`
- `notes` — 특이사항 (회전됨, 저해상도 등)

## 전사 규칙

이 규칙을 어기면 **OCR이 맞힌 것도 오류로 계산된다.** 규칙 자체가 측정의 일부다.

1. **읽히는 그대로 적는다.** 원문의 오탈자도 그대로 — 우리가 고치면 OCR이 정확히 읽은
   것이 틀린 것으로 집계된다.
2. **줄바꿈은 시각적 줄 단위로 유지한다.** 문단으로 합치지 않는다.
3. **표는 셀을 탭(`\t`), 행을 줄바꿈으로** 구분한다. 병합 셀은 첫 열에만 적는다.
4. **그래프는 축 라벨·범례·데이터 라벨만.** 그래프 모양을 말로 묘사하지 않는다.
5. **판독 불가 글자는 `[?]` 한 칸.** 글자 수만큼 적고, 추측해서 채우지 않는다.
6. **장식용 글머리 기호(•, ·)는 적지 않는다.** 번호 매김(`1.`, `가.`)은 적는다.
7. **수식은 보이는 문자 그대로.** LaTeX로 바꾸지 않는다.
8. **텍스트가 전혀 없는 이미지는 대장에서 제외한다.** 빈 파일을 만들지 않는다.

## 작업 순서

```bash
# 1. 진척과 층화 균형 확인 (수시로)
npm run check:ocr-goldenset

# 2. 다 모았으면 완성 판정 — 목표 미달·층화 이탈이 실패로 잡힌다
npm run check:ocr-goldenset -- --complete

# 3. 데이터셋 레지스트리에 봉인 (이후 변경은 CI 가 막는다)
npm run check:datasets -- --lock ocr-goldenset-v1

# 4. 측정 (OCR 백엔드 호출 — 비용 발생)
npx tsx scripts/eval-ocr.mjs datasets/ocr-goldenset --backend auto
```

3번을 빠뜨리면 안 된다. 봉인하지 않은 테스트셋은 조금씩 고쳐지고, 그러면 점수가
오른다 — 고의가 아니어도 애매한 표본을 지우는 방향으로 손이 간다(가이드 §10.2).

## 검사기가 잡는 것

- 대장에 `transcribed=y`인데 `.txt`가 없음
- 대장에 없는 고아 `.txt` 파일 (측정에서 조용히 섞이거나 빠진다)
- 빈 전사
- 알 수 없는 `stratum`
- 층화 목표 이탈 (평소엔 경고, `--complete`에서는 실패)
- 목표 총량 미달/초과
- 전사 규칙 위반 (장식 글머리 기호, 잘못된 `[?]` 표기)
